# ResolveLab v0.2.1 review evidence

The current review is separate from the frozen v0.2.0 release manifest. Its
output directory is `artifacts/recheck-2026-11-23/`. The builder never upgrades
old Linux, container, backup, install or dependency-audit evidence into current
v0.2.1 passes.

After application and verification source edits finish, run from the repository:

```powershell
.venv/Scripts/python.exe scripts/review_native.py
.venv/Scripts/python.exe scripts/review_release.py --ui-work-dir ../../work/recheck-resolvelab-pagination
.venv/Scripts/python.exe scripts/review_release.py --verify
```

The native runner invokes the guarded `scripts/run_tests.py` against the dedicated
disposable test database. It records the complete 173-case JUnit result, requires
zero failures, errors and skips, records a separate exposure scan, and binds both
to identical input snapshots before and after execution. It does not expose
database URLs or credential values in its summary. Inspection logs stay under
the versioned native directory. A failed or interrupted rerun cannot reuse a
previous successful verification file. Completed prior native runs are copied
to `native-history/` with an explicit superseded status before a new run begins.

The builder consumes completed browser and evaluation proof from
`../../work/recheck-resolvelab/` by default; `--work-dir` selects another completed
proof directory with the same layout. `--ui-work-dir` can select a separate
final browser proof directory while evaluations, backup and dependency evidence
remain in `--work-dir`. The pagination semantic fix uses
`--ui-work-dir ../../work/recheck-resolvelab-pagination`. It requires 54 browser checks across the
live workflow, mocked HTTPS OIDC and intercepted UI suites, 24 responsive checks,
nine axe states without reported violations and three keyboard checks. It checks
current frontend hashes, live source snapshots before and after the run, and
five source-bound frozen evaluation reports. Frozen model and dataset inputs
must retain their recorded hashes. Evaluation workflow failures remain in the
manifest; success of the evidence collector does not mean every model prediction
or synthetic workflow succeeded.

The collected reports, source hashes, native proof and final source-exposure
scan are hashed in `review-manifest-v0.2.1.json`. `--verify` fails if any recorded
evidence or covered source input has changed. Source/configuration edits require
a new native run. Backend or frontend edits also require the corresponding
evaluation or browser runs. Documentation and Git commits can be completed after
collection; hashes, rather than the pre-collection Git HEAD, identify tested
application content.

The current native backup check restores a new owned copy and verifies tracking
and approval, source-database preservation, and cleanup. Its source and report
hashes are collected separately from historical backup reports.

The current dependency audit covers the exact current locked Python and npm
package versions against OSV and the official npm registry. It records the query
time and zero observed advisory matches; it does not establish overall security.

Current-source Linux and CI have not been verified, the backend has not been
hosted, and Docker/install checks have not been refreshed in this review. The manifest records these gaps explicitly and references earlier
reports only as historical evidence. The available free cloud execution quota
was exhausted and no WSL distribution was configured; the review does not incur
paid execution or assert an unperformed rerun.
