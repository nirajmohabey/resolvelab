# What the ResolveLab measurements establish

The strongest model result is a **workflow-coverage improvement on the same frozen workload**, accompanied by an explicit error tradeoff. V4 matched 139/160 outcomes, versus 95/160 for v3 and 76/160 for the source classifier. Its raw routing macro-F1 was 0.8705 versus 0.8691 for v3. That small classification change should not be presented as a large generalization gain. More correctly routed cases passed the development-selected operating point; accepted coverage rose from 54/160 to 104/160, while accepted errors rose from 1/54 to 4/104. Every release accepted one unsupported case out of 40.

The main failure category is still **supported requests treated as unsupported**. Of v4's 21 failures, 17 are supported-to-unsupported routes, three are wrong supported routes, and one is unsupported-to-tracking. Human handoff is weakest at 28/40 recall. Six human requests were denied by explicit topic guards; they still escalated, but violated the expected routing/reason contract. One human request became a cancellation proposal, demonstrating why a trained routing decision must not authorize an order mutation. Exact-proposal approval and deterministic customer/tenant/state checks remain mandatory.

The initial source classifier's very high synthetic-source score masked weak ordinary-language behavior. Domain data, structured failure analysis, versioned semantic features, separate calibration, and core regressions address that gap. The new 160-case audit was held by a separate author until v4 froze; no post-audit training, threshold changes, or label edits were used to improve it. Group-bootstrap intervals retain the 87 meaning groups rather than pretending related variants are independent. They quantify sensitivity within this authored audit, not a representative-customer error bound.

The retrieval experiment also rejects an easy technology claim. Hybrid search did not win. Correcting lexical query semantics from all-term matching to any-term matching dramatically improved its ranking, while dense search had the best development ranking and remained strongest on the 16 held-out synthetic queries. Dense section recall@3 was 0.84375, compared with 0.8125 for lexical OR and 0.78125 for OR hybrid. The main demo has four policy sections; the harder benchmark has 32 permitted sections among 80 physical sections and exercises real permission filtering before ranking. Ranking relevance is separate from factual answer support.

A joint split audit found three validation/core duplicates. The full raw selection report remains available. Removing those source-validation rows keeps the selected parameters unchanged and leaves the original safety gate satisfied. Source/domain test and the new blind 160-case set have zero exact training overlaps. This does not rule out every semantic paraphrase, so source/family scores remain labeled synthetic distribution measurements.

Actual response safety tests check schema, allowlisted operations, required policy sections, real citation provenance, authorized order facts, role/tenant boundaries, and one-effect transactions. They do not constitute human factual review. The supplied review queue is intentionally unfilled; human claim support and paid-provider quality/cost remain unavailable. The optional LLM adapter is constrained to an approved bounded answer, with deterministic rendering as the reproducible default.

The release decision is therefore **operator-reviewed synthetic use**. Predeclared development/core gates and authorization/effect checks passed; the final audit's accepted errors and missed escalations remain public. Real merchant deployment needs reviewed domain data, operational monitoring of the observed failure categories, deployment-specific identity/secret configuration, and independently evaluated provider behavior if enabled.

Reproduce the measured paths with `scripts/run_final_paired_evaluation.py`, inspect `artifacts/v4/final-analysis/analysis.json`, and regenerate static snapshots with `scripts/publish_model_reports.py`. These commands use the dedicated disposable evaluation DB; training reproduction uses an isolated source copy and preserves serving manifests.
